## 1. Law summary (binding)

| Rule | Statement |
|------|-----------|
| Exhaustive inventory | Every interactive UI control shipped must appear as a row in the canonical inventory |
| **REQUIRED must PASS for dogfood** | A claimed `dogfood_ready` requires **every REQUIRED** inventory row status `PASS` with evidence, or an **owner DEFER** row |
| 1:1 Playwright map | Suite maps `test_id` 1:1 to inventory IDs; CI fails if a REQUIRED row lacks a test or the test fails |
| **No shrinkage** | Shrinking REQUIRED inventory to pass CI is **forbidden** (constitution Article III). Only owner DEFER removes a row from the required PASS set |
| **No wildcard-only acceptance** | Ownership and section proof cells must list exact IDs or explicit letter ranges with named owners — wildcards alone (`A*`, `D*`, “full inventory”) are **forbidden** as the sole acceptance criterion |
| Unlisted control = defect | Interactive control discovered in UI but missing from inventory is a defect until inventoried or removed |
| **Discovery crawl REQUIRED at Phase 8.x** | Admin primary-action discovery crawl is **REQUIRED** at Phase 8 (not optional hardening) |
| Phase 8 full run | Phase 8 keystone runs the full Playwright suite; report HTML in `reports/e2e-coverage.html` |

**Statuses (inventory column):** `OPEN` | `IMPLEMENTED` | `PASS` | `FAIL` | `DEFER` (owner only)

## 2. REQUIRED column semantics

| Value | Meaning |
|-------|---------|
| **REQUIRED** | Must **PASS** for `dogfood_ready`. CI fails if the row is REQUIRED and not PASS at the Phase 8 gate (after implementation). |
| **OPTIONAL** | Hardening only — not part of the dogfood PASS set |
| empty (matrix M only) | Coverage map row — **not** a journey count; do not double-count |

**Definition (ratified):**  
`REQUIRED` = must PASS for dogfood_ready. Every journey row in tables A–L and N–O carries `REQUIRED` unless an **owner DEFER** is recorded. Section **M** is a settings coverage matrix only (maps to O/N/C/D/J/K IDs) and is **not** a journey count.

**Canonical count at ratification:** **108** unique journey IDs, all **REQUIRED**, all status `OPEN` until implemented. Letter areas: A–L, N, O (no M journeys).

**Lifecycle:**

1. Feature section ships UI → row status may move `OPEN` → `IMPLEMENTED` in the same PR as the feature (and inventory row if new).  
2. Phase keystone / proof owner runs Playwright for owned IDs.  
3. Phase **8.2 / 8.5** require **all non-DEFER REQUIRED** rows `PASS` with evidence.  
4. Status `DEFER` only via owner amendment — not builder convenience.

## 3. Tagging convention `@inv:A01`

Playwright tests **must** tag inventory IDs so inventory lint and humans can map tests 1:1.

| Rule | Example |
|------|---------|
| Format | `@inv:` + inventory ID (letter + two digits) |
| Single journey (strict 1:1) | `@inv:A01` |
| One `@inv` tag per `test()` title | Multi-tag titles (e.g. `@inv:I06` `@inv:I16` on one test) are **rejected** — each inventory ID needs its own test declaration |
| File / title | Prefer `test_id` path from inventory (e.g. `e2e/public/cfp-load`) |

**Example (Playwright):**

```ts
import { test, expect } from "@playwright/test";

test("@inv:A01 public CFP loads form and brand tokens", async ({ page }) => {
  // journey: Load form; see welcome; brand tokens visible
  // negative: 404 invalid slug
});
```

**Lint expectations (`pnpm test:e2e:inventory`):**

- Every REQUIRED inventory ID has a unique non-empty `test_id` in the inventory file (1:1 inventory-to-test map; duplicate `test_id` values fail).  
- Anti-shrinkage validates the **exact** ratified baseline ID set in `scripts/e2e-inventory-required-baseline.json` (not a count alone).  
- Anti-reuse validates **stable fingerprints** (`test_id` + `journey` text) for each baseline ID — reusing an ID for different behavior fails even if the ID string remains.  
- **@inv tag decision table** (intermediate vs Phase 8 — single coherent rule, no empty-root loophole):  
  - **Intermediate phases:** every **IMPLEMENTED / PASS / FAIL** (status-owned) non-DEFER REQUIRED ID must have a matching `@inv:XX` tag under an e2e root (`playwright/e2e`, `e2e/`, or `apps/web/e2e`). Claiming status-owned without test files is a **failure** — an empty or missing e2e root does **not** defer coverage when any status-owned ID exists. OPEN rows need not be tagged until the owning section implements them.  
  - **Phase 8 gate:** `E2E_INVENTORY_GATE=phase8 pnpm test:e2e:inventory` requires `@inv` tags for **all** non-DEFER REQUIRED IDs. Absence of an E2E root or test files is a **failure** in full-gate mode (coverage is not deferred).  
  - **Pre-harness deferral only:** when every journey is still `OPEN`/`DEFER` and the gate is not phase8, tag coverage may be deferred even if an empty e2e directory already exists.  
- **`@inv` must sit on a real Playwright `test(...)` / `test.only(...)` title** — comments, bare strings, or other non-test occurrences do **not** count. Lint also fails on: multi-tag titles (more than one `@inv:ID` on a single test), skipped/fixme/fail-only coverage (`test.fail()` is expected-failure and is not dogfood proof), duplicate active owners for one ID, `test.only` at Phase 8, and titles/files that are not anchored to the inventory `test_id`.  
- No skipped, fixme, expected-failure (`test.fail`), or focused tests on REQUIRED journeys at Phase 8 full run.  
- Wildcards are not a substitute for exact `@inv` tags.

**UI data attributes (when components land):** Prefer stable selectors tied to inventory (e.g. `data-inv="A01"` on journey roots) where useful; tags on tests remain mandatory.

## 5. Anti-shrinkage (no inventory shrinkage)

**Forbidden:**

- Deleting REQUIRED rows to make CI green  
- Reusing an inventory ID for different behavior  
- Downgrading REQUIRED → OPTIONAL without owner DEFER / amendment  
- Claiming PASS on a wildcard subset while REQUIRED rows remain OPEN/FAIL  
- Emptying the REQUIRED set via “lint only OPEN rows we care about”

**Allowed:**

- **Adding** rows when new UI controls ship (same PR)  
- Status transitions OPEN → IMPLEMENTED → PASS/FAIL  
- Owner **DEFER** with recorded rationale (removes from required PASS set only for that DEFER)  
- Fixing typos in journey text without changing ID semantics

**Baseline (ratified at 0.3):** Inventory lint persists the **exact** set of **108** REQUIRED IDs **and** per-ID fingerprints (`test_id` + `journey`) in `scripts/e2e-inventory-required-baseline.json`. Future lint must not accept deletion, rename, silent replacement of any baseline ID, or reuse of a baseline ID for different behavior (fingerprint drift). A baseline ID may leave the required PASS set only with status **DEFER** (owner amendment) while the row remains present — count-only checks are insufficient (replacing A01 with a new ID while keeping count ≥ 108 is **forbidden**). Intentional journey wording or `test_id` path updates require re-ratifying the matching fingerprint. Growth above baseline is expected as UI expands.

**Rule:** Discovery crawl is **REQUIRED at Phase 8** for admin primary actions.

| Item | Requirement |
|------|-------------|
| Scope | Admin primary actions (and shipped surfaces as crawl expands) |

| Allowlist | Pure chrome only (non-action decorative chrome), documented |
| Timing | Phase **8.x** (inventory completeness 8.1 + full run 8.2; crawl mandatory before dogfood claim) |
| Not optional | Earlier advisories marked crawl “optional hardening” — **superseded**: crawl is REQUIRED at 8.x |

Unlisted interactive control → defect until inventoried or removed (constitution + inventory law).
