## 1. Person ≠ Speaker (domain rule)

**Person ≠ Speaker.** A **Person** is the durable org-level identity (`people` table: email, name). A **Speaker** (or other role) is an **event participation** (`event_participations`: person + event + role_label, status, bio, tasks, files) — not a separate person row per event, and not a synonym for `users` (login identity).

| Concept | Table / model | Meaning |
|---------|---------------|---------|
| **Person** | `people` | Canonical durable identity (`org_id`, email, name) |
| **Participation / “speaker at event”** | `event_participations` | Person linked to an event with status, bio, headshot, tasks |
| **User** | `users` + `event_memberships` | Login identity; may attach to a participation via `user_id` |
| **Submission speaker** | `submission_speakers` | Person on a CFP submission (pre-accept) |
| **Session speaker** | `session_speakers` | Participation on a program session (post-accept / direct) |

**Implications (builders):**

- Do not collapse person and participation into one mutable “speaker” table keyed only by event.
- Accept side-effects create or link **participations** and tasks; they do not fork a second person identity.
- Admin “Speakers” UI is over **participations** (and related tasks/files), joined to **people**.
- **Submission ≠ Session** remains the companion rule (application vs program slot).

Source: synthesis keep-list; schema ownership for `people` / `event_participations` in SCHEMA.md; clean-room model in 0.1.

## 3. Command list summary

Canonical detail: [`COMMANDS.md`](../../KMS-competition/initiative/contracts/COMMANDS.md).

| Domain | Commands (summary) | Primary scopes / roles |

| Evaluation & decisions | `Eval.UpsertRubric`, `Eval.Score`, `Decision.Record` | evaluator score; **`decisions:write`** |
| Portal & files | `Portal.GetHome`, `Participation.UpdateProfile`, `File.PresignUpload`, `File.Upload`, `File.CompleteUpload`, `File.GetPublic`, `Task.Complete` | speaker / admin / `files:write` / public get |

### CLI parity (S-CLI)

```text
speakerops <resource> <verb> --json  →  same domain command as HTTP
```

Examples: `speakerops reports readiness --event E --json` → `Reports.Readiness`.  
No parallel god-mode CLI that bypasses this registry. Full CLI proof list: [`CLI_INVENTORY.md`](../../KMS-competition/initiative/contracts/CLI_INVENTORY.md).

### HTTP route map (pointer)

Canonical table lives in COMMANDS.md (§ HTTP route map). Representative routes:

| Method | Path | Command |
|--------|------|---------|
| POST | `/api/submissions/:submissionId/decision` | `Decision.Record` |
| POST | `/api/comms/send` | `Comms.Send` |
| POST | `/api/keys` | `Keys.Create` |
| DELETE | `/api/keys/:keyId` | `Keys.Revoke` |

## 4. Scope matrix summary (default-deny)

Canonical detail: [`SCOPES.md`](../../KMS-competition/initiative/contracts/SCOPES.md).

| Scope | Commands allowed (summary) | Default on new keys |
|-------|----------------------------|---------------------|
| `events:read` / `events:write` | Event list/get / create update | grant only if requested |
| `cfp:read` / `cfp:write` | Forms admin (not public submit) | grant only if requested |
| `submissions:read` / `submissions:write` | List/get/assign | grant only if requested |
| **`decisions:write`** | `Decision.Record` | **default deny** on new keys |
| `speakers:read` / `speakers:write` | Portal-equivalent admin edits | grant only if requested |
| `files:write` | Presign/complete | grant only if requested |
| `schedule:read` / `schedule:write` | List / place move unschedule | grant only if requested |
| `comms:draft` | `Comms.Preview` | grant only if requested |
| **`comms:send`** | `Comms.Send` | **default deny** (send) |
| `design:read` / `design:write` | Design get/set/publish | grant only if requested |
| `reports:read` | Readiness, exports | grant only if requested |
| `airtable:read` | Projection status | grant only if requested |
| **`keys:admin`** | Mint/revoke keys | **default deny** |

### Default-deny high-risk (explicit)

Scopes that **must not** be present on a newly created key unless explicitly granted:

1. **`comms:send`** — outbound email/send jobs (`Comms.Send`)
2. **`decisions:write`** — accept/reject/waitlist (`Decision.Record`)
3. **`keys:admin`** — mint/revoke API keys (`Keys.Create` / `Keys.Revoke`)

**Enforcement:** Server-side only (E10). Never trust CLI flags or UI alone. Wrong scope → 403 (or 404 per policy) with tests. Browser roles: admin ⊂ most scopes; evaluator ⊂ score only; speaker ⊂ portal; public ⊂ submit only.

## 5. Alignment rules (FE / CLI / API)

| Surface | Composition root (post-scaffold) | Obligation |
|---------|----------------------------------|------------|
| API | `apps/api/src/index.ts` | Register only COMMANDS.md handlers; Zod + authz + audit |
| Web | `apps/web/src/main.tsx` | Call real HTTP commands; shared DTOs from `packages/shared/src/` |
| CLI | `packages/cli/src/main.ts` | 1:1 command names; scopes via API keys |
| DB | `packages/db` | SCHEMA.md tables only |
| Shared DTOs | `packages/shared/src/` | Single source — no duplicate types across web/api |

**Builder must not invent:**

- Endpoints or table columns outside COMMANDS.md / SCHEMA.md without updating those contracts in the same PR
- A second source of truth (Airtable dual-write, DO-as-DB, client-only authz)
- Placeholder soul UI that does not call real APIs
- Parallel god-mode CLI bypassing domain commands
- Weakening cookie flags, CSP, or scope checks for demo convenience
- Secrets in repo (env **names** only)
