## 3. Contrast gate rule

**Rule:** Design Kit **publish** validates brand vs on-brand text before publish succeeds.

| Check | Requirement |
|-------|-------------|
| Primary button on public CFP | Brand fill + derived label color must meet **WCAG AA** contrast |
| Label derivation | Auto-derive light/dark label color from brand luminance |
| Failure | **Block publish** with machine-readable validation error (Zod/domain code) — do not ship low-contrast public CTAs |
| Soft tint | `brandSoft` is decorative; primary actions use strong brand + AA label |

Invalid hex → reject (inventory negatives). Contrast fail → reject publish (not silent clamp).

CLI parity: `speakerops design get|set|publish` enforces the same gate as UI (when CLI lands).

## 4. Retheme blast radius

**Invariant — retheme blast radius:** **Public CFP + speaker portal only** adopt event brand tokens.

| Surface | Brand retheme? |
|---------|----------------|
| Public CFP | **Yes** — published tokens |
| Speaker portal | **Yes** — published tokens |
| Admin chrome | **No** — always Lumen default |
| Evaluator chrome | **No** — always Lumen default |

**Why:** An ugly event brand must not destroy daily ops surfaces. S-THEME requires public CFP to reflect brand without code deploy; it does **not** require admin retheme.

Draft tokens must not leak to public CFP until publish.

## 5. Design Kit security (SVG reject + tokens only)

| Control | Safe | Unsafe |
|---------|------|--------|
| Brand color, soft tint | ✓ CSS vars + **contrast gate** (§3) | Unchecked low-contrast hex |
| Logo image | ✓ PNG / WebP / JPEG as inert `<img>` from R2 | **SVG rejected** in dogfood unless later constitution/amendment with proven sanitizer; never inline script; never execute uploaded markup |
| Radius scale (soft / curvy / round) | ✓ maps to radius tokens | |
| Wordmark text | ✓ escaped text | |
| Freeform CSS / JS / HTML | | ✗ **forever** |
| Draft vs publish | ✓ draft local to admin until publish | Draft tokens must not leak to public CFP |

**SVG reject language (binding for dogfood):**  
Logo uploads that are SVG (or content-type `image/svg+xml`) are **rejected**. Raster formats only. No partial sanitizer path in dogfood. Serve logos as inert images with CSP/`img` constraints when implemented.

### Product chrome structure (IA lock)

```
Admin: Overview | CFP / Forms | Submissions | Evaluations | Speakers | Schedule | Comms | Settings
         Settings → Event · Rooms/Tracks · Tasks · Design (Brand) · API Keys · Airtable status
Evaluator: My queue only
Speaker: Tasks | Profile | My sessions
Public: CFP form only
```

Active event always visible on admin mutating surfaces. No CRM/Marketing/CMS module zoo.

### UX laws (binding)

1. **One job per surface** (public form vs portal vs eval vs admin schedule).  
2. **Trust before automation** — comms must show exact audience count + rendered body + missing merge fields before send.  
3. **Schedule is hero** — snap, ghost, plain-language conflicts, undo, keyboard alternative.  
4. **Speed as brand** — optimistic ticks; on reject **revert + toast**.  
5. **Theme via tokens only** — no freeform CSS/HTML.  
6. **Role-appropriate starts** — admin → readiness; evaluator → queue; speaker → next task.  
7. **Status never color-only** — label required.  
8. **Focus visible** — `--lumen-focus-ring` on all interactive controls.
