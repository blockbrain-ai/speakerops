## Schema (SCHEMA.md)

### rooms
`id, event_id, name, capacity, created_at, updated_at, version`

### tracks
`id, event_id, name, color, created_at, updated_at, version`

Event-scoped queries always take `eventId` at the repository/store layer (E2).

## Interfaces

```http
POST   /api/events
GET    /api/events
GET    /api/events/:eventId
PATCH  /api/events/:eventId
GET    /api/events/:eventId/rooms
GET    /api/events/:eventId/rooms/:roomId
PUT    /api/events/:eventId/rooms/:roomId
GET    /api/events/:eventId/tracks
GET    /api/events/:eventId/tracks/:trackId
PUT    /api/events/:eventId/tracks/:trackId
```

Authz: admin role via `requireRole` (session). Unauthenticated → 401; wrong role → 403;
no membership on target event → 404 (cross-event isolation). Validation → 400 E4 envelope.
Consequential writes emit `audit_events` with `correlationId` (E3).

## Performance notes

- Primary admin list (`GET /api/events`) is membership-scoped in-memory store for local/e2e;
  target p95 &lt; 200ms after warm for seed ≤150 rows (unit path is O(memberships)).
- Settings page loads rooms/tracks for active event only (event-scoped).
