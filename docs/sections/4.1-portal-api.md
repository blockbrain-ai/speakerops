## Schema (SCHEMA.md)

Tables owned by 3.5 / 4.1 (created in `0010_decisions.sql`):

### people
`id, org_id, email, name, created_at, updated_at` — canonical identity (Person ≠ Speaker)

### event_participations
`id, event_id, person_id, user_id NULL, role_label, status, bio, company, title, headshot_file_id, version, created_at, updated_at`  
UNIQUE(event_id, person_id)

### task_templates
`id, event_id, title, description, trigger (on_accept|manual), due_offset_days, version, created_at`  
Optimistic `version` (E1; migration `0014_task_templates_version.sql`) — required on Update/Delete.

### speaker_tasks
`id, template_id, participation_id, status, due_at, completed_at, version, created_at, updated_at`  
UNIQUE(template_id, participation_id)

## Accept → portal link

On Decision.Record accept (3.5):
1. Materializes `event_participations` + `speaker_tasks` from `task_templates` (`on_accept`)
2. Portal.GetHome resolves ownership by `participation.user_id` or person email match
3. First portal access links `user_id` on the participation

## Authz / security

- Portal home / complete / profile: **speaker** (or admin) membership on event; **own** participation/tasks only
- Completing another speaker’s task → **403** FORBIDDEN
- Speakers list/detail + templates: **admin** role on event
- Unauthenticated → **401**
- Invalid body → **400** VALIDATION_ERROR (E4 envelope)
- `expectedVersion` mismatch → **409** CONFLICT
- Consequential writes emit `audit_events` with `correlationId` (E3)
- No dual-write Airtable; no secrets in repo
