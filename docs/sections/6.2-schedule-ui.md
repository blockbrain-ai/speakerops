## Interfaces (UI → Schedule.*)

| UI action | Command | HTTP |
|-----------|---------|------|
| Load studio | Schedule.List | `GET /api/events/:eventId/schedule` |
| Drag / keyboard place | Schedule.Place | `POST …/schedule/place` |
| Drag move / keyboard move | Schedule.Move | `POST …/schedule/move` |
| Unschedule / undo place | Schedule.Unschedule | `POST …/schedule/unschedule` |
| Rooms / tracks labels | Room.List / Track.List | existing 2.3 routes |

No new endpoints beyond 6.1. Place/Move still enforce hard conflicts (409 CONFLICT) and optimistic version (409 VERSION).

## Failure modes addressed

| Mode | Mitigation |
|------|------------|
| Conflict still commits | 409 + conflict toast; placement count unchanged (I07/I08) |
| Keyboard cannot place | Select tray item → focus slot → Enter/Space (I09) |
| View desync after reload | List from server; I16 reload assertion |
| No undo | Client undo stack inverse of last successful mutation (I10) |
| Silent overwrite | Stale recovery panel + Refresh (I15) |

## Lumen / a11y

- Schedule **tile** component (`.schedule-tile`) — brand-soft surface, Lumen tokens only
- Focus rings via `.lumen-focusable` on tabs, tray items, slots, tiles, undo
- Conflict toast uses danger soft pair (not color-only)
- Admin chrome stays Lumen default (no brand retheme)

## Performance notes

- Primary admin list interactions target p95 &lt; 200ms local after warm load for seed ≤150 rows
- Studio loads schedule + rooms + tracks in parallel; skeleton/loading text while fetching
- No multi-second blank screen — tray + toolbar render immediately when event selected

## Observability

- Mutations use cookie session; Worker propagates `correlationId` (6.1 handlers audit Place/Move/Unschedule)
- No secrets or magic-link tokens logged in UI
