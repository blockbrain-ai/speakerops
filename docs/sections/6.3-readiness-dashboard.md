### Reports.Readiness response

```json
{
  "eventId": "…",
  "stats": {
    "totalSpeakers": 0,
    "speakersWithOutstanding": 0,
    "outstandingTasks": 0,
    "overdueTasks": 0,
    "completedTasks": 0,
    "cancelledTasks": 0
  },
  "outstanding": [
    {
      "taskId": "…",
      "participationId": "…",
      "personId": "…",
      "personName": "…",
      "personEmail": "…",
      "taskTitle": "…",
      "templateId": "…",
      "status": "pending|overdue",
      "dueAt": "…",
      "isOverdue": false,
      "version": 1
    }
  ],
  "generatedAt": "ISO-8601"
}
```

Query: `overdueOnly=true|1` filters `outstanding[]` to overdue only (stats remain full-event).

### Overdue definition

Incomplete task is overdue when `status === "overdue"` **or** `dueAt ≤ now` (`isTaskOverdue` in `@speakerops/shared`).

## Authz

- Role: **admin** only (evaluator/speaker → 403; no membership → 404)
- Scope (API keys, Phase 7): `reports:read`
- Unauthenticated → 401; invalid query → 400 VALIDATION_ERROR

## Live update (H04)

- UI polls `GET …/readiness` every **3s** (`READINESS_POLL_MS = 3000` ≤ 5s)
- No Durable Object required for dogfood; poll is sufficient for S-READY
- After speaker `Task.Complete`, next poll decreases outstanding without full page reload

## Failure modes addressed

| Mode | Mitigation |
|------|------------|
| Unauthenticated | 401 E4 |
| Wrong role | 403/404 |
| Bad query | 400 VALIDATION_ERROR |
| Cross-event leak | event-scoped participations/tasks only |
| Placeholder dashboard | Real API wire; empty state only when stats are zero |

## Performance notes

- Primary admin list interactions target **p95 &lt; 200ms** local after warm load for seed ≤150 rows (L05 uses client-side page size 25; Speakers.List returns full set once).
- Readiness poll is quiet (no loading flash); first load shows “Loading readiness…”.
- No multi-second blank screen — toolbar + filter render immediately when event selected.

## Observability

- Read is non-mutating (no audit_events); Task.Complete (prior section) audits with correlationId.
- Correlation header propagated on Worker requests.
- No secrets / magic-link tokens in UI or logs.

## Lumen / a11y

- Stat cards use Lumen surface/border/shadow tokens only (E6)
- Overdue rows use danger soft badge (not color-only — status text present)
- Focus rings via `.lumen-focusable` on filter, refresh, drill links, pager
