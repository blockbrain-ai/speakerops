## Schema (SCHEMA.md)

### email_templates
`id, event_id, key, subject, body_md, version, created_at, updated_at`  
UNIQUE(event_id, key)

### message_jobs
`id, event_id, template_id, status (preview|queued|…), segment_json, recipients_json, bodies_json, missing_fields_json, idempotency_key, created_by, version, created_at, updated_at`  
Jobs carry `idempotency_key` (SCHEMA). Partial unique on non-null key.

### outbox_events (existing baseline)
Topic `comms.send` payload: `{ jobId, eventId, templateId, idempotencyKey, correlationId }`.  
`processed_at` remains null until section 5.2 provider drain.

## Interfaces

SPA:
- `GET /admin/comms` → template editor (key, subject, body, merge-field list)

## Authz / security

- Upsert / preview / send: **admin** role on target event (session)
- API key scopes `comms:draft` / `comms:send` apply in Phase 7; session path uses roles
- Unauthenticated → **401**
- Wrong role → **403** (or **404** cross-event isolation)
- Invalid body/key → **400** VALIDATION_ERROR (E4)
- Version conflict → **409** CONFLICT
- Consequential writes emit `audit_events` with `correlationId` (E3)
- **No** provider HTTP (Resend/SendGrid/SES/SMTP) on the command path (E7)
- No secrets in repo; env **names** only (provider keys land with 5.2)
