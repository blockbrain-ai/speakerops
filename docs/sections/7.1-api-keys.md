### Keys.Create body

```json
{
  "name": "CLI read",
  "scopes": ["events:read", "reports:read"],
  "eventId": null,
  "expiresAt": null
}
```

### Keys.Create response (secret once)

```json
{
  "id": "…",
  "secret": "spk_<prefix>_<secret>",
  "prefix": "spk_<prefix>",
  "name": "CLI read",
  "scopes": ["events:read", "reports:read"],
  "eventId": null,
  "expiresAt": null
}
```

### Keys.List response

```json
{
  "keys": [
    {
      "id": "…",
      "orgId": "org_dogfood",
      "name": "CLI read",
      "prefix": "spk_…",
      "scopes": ["events:read"],
      "eventId": null,
      "expiresAt": null,
      "revokedAt": null,
      "createdBy": "…",
      "lastUsedAt": null
    }
  ]
}
```

**Never returned:** full `secret`, `key_hash`.

## Data / schema

`api_keys`: `id, org_id, name, key_prefix, key_hash, scopes_json, event_id NULL, expires_at, revoked_at, created_by, last_used_at, created_at`

`created_at` was added in migration `0022_api_keys_created_at.sql` (the 0018 baseline omitted it); the column is NULL-tolerant with a fallback for rows minted before the migration.

## Security

- Plaintext secret generated client-bound on create only; **SHA-256 hex** stored as `key_hash` (same primitive as sessions).
- Bearer: `Authorization: Bearer <secret>` → hash lookup; revoked/expired/missing → **401**.
- Wrong role/scope → **403** with E4 envelope.
- Default-deny (must opt in): `comms:send`, `decisions:write`, `keys:admin`.
- Audit on Create/Revoke with `correlationId`; audit payload never includes secret.
- No secrets in repo; env **names** only (E10).

## Performance notes

- Admin key list: in-memory/D1 single-table scan; seed ≤150 keys targets p95 &lt; 200ms local after warm (measurement deferred to ops harness; no heavy joins).
