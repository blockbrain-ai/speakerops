## Schema (SCHEMA.md)

### event_memberships
`id, event_id, user_id, role (admin|evaluator|speaker), created_at`  
UNIQUE(`event_id`, `user_id`)

Magic-link purpose (`admin` / `speaker` / `evaluator`) upserts a membership for
`eventId` or dogfood default `evt_dogfood` so bootstrap sessions carry a role.

## HTTP 401 / 403 / 404 matrix

| Condition | Status | Code |
|-----------|--------|------|
| No / invalid / expired session | **401** | `UNAUTHORIZED` |
| Authenticated but wrong role (e.g. speaker on admin list, evaluator on schedule write) | **403** | `FORBIDDEN` |
| No membership on target event (cross-event isolation) | **404** | `NOT_FOUND` |
| Validation failure | **400** | `VALIDATION_ERROR` |
| Unexpected throw | **500** | `INTERNAL_ERROR` (no stack to client) |

Cross-event policy: missing membership returns **404** (not 403) so clients cannot
probe existence of events they are not a member of.

## Interfaces

```ts
// API
requireRole(store, ["admin"], { eventIdFrom: "none" })   // Event.List
requireRole(store, ["admin"], { eventIdFrom: "param" })  // event-scoped writes

// UI
<RequireRole roles={["admin"]}>…</RequireRole>
// Probes GET /api/events; 401 → /login; 403 → Access denied
```
