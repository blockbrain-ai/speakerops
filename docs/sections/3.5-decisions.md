`id, submission_id, decision (accept|reject|waitlist), reason, decided_by, created_at`

`id, event_id, person_id, user_id NULL, role_label, status, bio, company, title, headshot_file_id, version, created_at, updated_at`

## Accept materialization

On `decision=accept`:
1. Optimistic `submissions.status=accepted` (+ version++) **first** when status must change (claims the race; losers get 409 with no side effects)
2. Create programme `sessions` row with unique `source_submission_id` (idempotent)
3. Create `event_participations` for each submission speaker
4. Link `session_speakers`
5. For each `task_templates` with `trigger=on_accept` × each participation → `speaker_tasks`  
   If no templates exist for the event, seed two defaults (headshot + bio).
6. Upsert `decisions` + `audit_events` (idempotent retries repair missing side effects / audit)

Second accept with the same decision **and reason** is **idempotent** (no duplicate session/tasks; repairs incomplete side effects / audit).

Repeating reject/waitlist with a **changed reason** updates the decision row (not a silent no-op).

Partial apply (status advanced, decision/artifacts incomplete): retries — including with the original `expectedVersion` — complete remaining writes instead of hard-409.

On accept → reject/waitlist: cancel session and drop `session_speakers`; cancel tasks / withdraw participation **only** when the speaker is not still linked to another confirmed session.

## Authz / security

- Decision / list / get / direct / bulk-preview: **admin** role on event
- Evaluator Decision.Record → **403** FORBIDDEN (not 404)
- Unauthenticated → **401**
- Invalid body → **400** VALIDATION_ERROR (E4 envelope)
- `expectedVersion` mismatch on submission → **409** CONFLICT
- Consequential writes emit `audit_events` with `correlationId` (E3)
- No email send (5.x); no dual-write Airtable
