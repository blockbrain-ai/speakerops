## Schema (SCHEMA.md)

### message_recipients
`id, job_id, event_id, participation_id, to_email, name, subject, body, status, created_at`  
I16: recipient email from segment preview → `to_email`.

### delivery_events
`id, job_id, recipient_id, event_id, provider, provider_message_id, status, attempt, error, payload_json, created_at`  
Provider values: `sandbox` | `resend`. Status: `sandbox` | `sent` | `failed`.

### calendar_invites
`id, event_id, placement_id, session_id, uid, sequence, method, summary, starts_at, ends_at, location, ics_body, version, created_at, updated_at`  
UNIQUE(uid); UNIQUE(event_id, placement_id). METHOD: REQUEST | CANCEL.

### idempotency_keys (baseline)
Used by Comms.Send with storage key `comms.send:{idempotencyKey}` + request hash of `{previewId, idempotencyKey}`.

## Authz / security

- Preview / send: **admin** role on target event (session)
- Unauthenticated → **401**
- Wrong role → **403** (or **404** cross-event isolation)
- Missing `previewId` / invalid body → **400** VALIDATION_ERROR (E4)
- Idempotency key reused with different body → **409** CONFLICT
- Consequential writes emit `audit_events` with `correlationId` (E3)
- **No** provider HTTP on Comms.Send command path (E7)
- Provider secrets: env **names** only — `EMAIL_PROVIDER`, `RESEND_API_KEY`, `EMAIL_FROM` (E10)
- Sandbox is default unless `EMAIL_PROVIDER=resend` **and** `RESEND_API_KEY` set

## Performance notes

Send is a single D1 transaction path (job update + recipients + outbox + idempotency_keys).  
Outbox drain is async; request path does not wait on provider (E7).  
Warm p95 target for admin interactions remains &lt; 200ms local (seed ≤150 rows).
