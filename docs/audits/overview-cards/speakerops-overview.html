SpeakerOps

Clean-room Program OS for AI Engineer / Software 3.0 conference ops — CFP → evaluate → accept → portal → comms/calendar → schedule → readiness. Built to replace expensive tools like Sessionboard without cloning them.

Product thesis

  • Program OS, not a marketing/CRM suite — six core workflows end-to-end; no ticketing, travel, sponsor CRM, attendee app, or media studio.
  • Fewer surfaces, production-hard — not a thin MVP sprawl; each surface is typed, tested, and operable.
  • Person ≠ Speaker, Submission ≠ Session — durable identity vs event participation; applications don’t auto-become programme slots.
  • Human authority stays central — accept/reject and scheduling stay human; no AI multi-round review theatre, no auto-scheduler.
  • Exception-first readiness — “who’s blocking publish,” not another endless admin grid.
  • Performance and honesty as features — calm UI, status semantics not rethemed by brand, design tokens as published data.

Agents + CLI

  • speakerops CLI is first-class — maps 1:1 to the same domain commands as HTTP.
  • Scoped API keys (spk_…) — scopes enforced only on the Worker; CLI cannot elevate itself.
  • High-risk scopes default-deny — e.g. comms:send, decisions:write, keys:admin.
  • Agent-stable contract — --json, fixed exit codes (0 ok · 1 validation · 2 authz · 3 conflict · 4 network).
  • Real ops coverage — events, readiness, design, schedule, files, speakers, comms, keys, OpenAPI, CFP, decisions, eval.
  • Tiny CLI surface — essentially @speakerops/shared only; hand-rolled args + fetch.
  • Same commands for humans and agents — cookies/UI for people; CLI + keys + agent docs for machines.

Stack & supply chain

  • Frontend runtime deliberately tiny — React, ReactDOM, react-router-dom, shared only. No MUI/Chakra/Ant/Tailwind/Radix.
  • In-house Lumen UI — custom primitives + CSS tokens; zero new runtime deps without exception.
  • API runtime thin — Hono + Zod + Drizzle + workspace packages.
  • Cloudflare-native — Workers + D1 SoR + Queues/outbox.
  • Airtable projection — one-way push from D1 (source of truth) into Airtable, as judges asked; optional, no dual-write mess.
  • Supply-chain gate — pnpm audit:deps fails on high/critical; committed lockfile required.
  • CSP + cookies match the thin stack — production script-src 'self'; HttpOnly/Secure/SameSite sessions.
  • Integrity over cleverness — typed commands, server-side roles, audit, optimistic concurrency, idempotent sends, conflict explain.
Pitch — A command-first, Cloudflare-native Program OS: thin dependency blast radius, one-way Airtable projection from D1, the same typed commands for UI and agents, a full docs/contracts/E2E proof suite, and a real CFP→readiness loop for operators who also run Software 3.0.

SpeakerOps

Speaker experience · documentation · proof · scale of the build

Speaker experience

  • Portal onboarding as a real workflow — one step at a time (skip / save draft / continue); not a CTA over a full form dump.
  • Tasks that need answers get UI — freeform/confirm steps instead of orphan “Mark complete.”
  • Files + profile + sessions — plain-text XSS-safe bios and durable uploads.

Documentation suite

  • Full operator + agent docs — architecture, security, CLI, ops, secrets, E2E, troubleshooting, field flow, Airtable, competition map.
  • Section-level run notes — docs/sections/ aligned to the Section Runner programme.
  • Contracts as product — COMMANDS, SCHEMA, SCOPES, CLI_INVENTORY, inventory ownership.
  • Human + agent onboarding — ONBOARDING.md, AGENT_SETUP.md, HTML reports under reports/.
  • Audit trail — dual-auditor advisories, Phase 10/11 gap-close, competition thin-areas, handover/cosign evidence.

Proof culture

  • Inventory Playwright E2E — dozens of specs, plus unit/governance tests.
  • Dogfood deploy — Cloudflare www.speakerops.org with health/smoke evidence.
  • Dual-auditor / cosign discipline on major gates, not screenshot theatre.
